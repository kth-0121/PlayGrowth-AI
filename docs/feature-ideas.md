## 1. 생년월일 연도를 4자리로 제한 (P0)

**지금**
- 온보딩의 생년월일 칸(`<input type="date">`)에 연도가 6자리까지 들어갑니다. 예: `202405-03-01`
- 날짜 칸에 최솟값과 최댓값이 없어서 브라우저가 연도를 6자리까지 받기 때문입니다.

**제안**
- 날짜 칸에 `min`과 `max`를 넣어서 연도가 4자리로만 입력되게 합니다.
  - `min`: 오늘에서 만 7세를 뺀 날짜 (예: `2019-11-08`)
  - `max`: 오늘 (`2026-11-07`)
- 범위를 벗어나면 지금 있는 안내 문구를 그대로 보여줍니다. "만 0~6세(0~83개월) 아이만 이용할 수 있어요"
- 아이 정보를 다시 입력하는 화면에도 같은 규칙을 적용합니다.

**확인할 것**
- 연도에 `20245`처럼 5자리 이상을 입력할 수 없어야 합니다.
- 미래 날짜는 고를 수 없어야 합니다.

## 2. 오늘의 놀이를 마친 뒤 다른 놀이 이어서 하기 (P0)

**지금**
- 홈의 오늘의 놀이 카드에는 [놀이 시작]과 [다른 놀이] 버튼이 있습니다.
- 놀이를 하고 기록을 남긴 뒤에 "하나 더 해 볼까?"로 이어지는 길이 없습니다.

**제안**
- 기록을 저장한 화면에서 버튼 두 개를 보여줍니다.
  - **[다른 놀이 하기]**: 기록을 반영한 다음 추천 놀이로 바로 갑니다. 지금 있는 기록 기반 추천 규칙을 그대로 씁니다.
  - **[오늘은 여기까지]**: 홈으로 갑니다.
- 오늘 이미 기록한 놀이가 있으면 홈 카드의 표시를 바꿉니다.
  - 카드 위에 "오늘 1개 했어요 ✓"를 보여줍니다.
  - 버튼 문구를 [놀이 시작] 대신 **[다른 놀이도 해 볼까요?]**로 바꿉니다.
- 놀이는 많이 하는 것보다 꾸준히 하는 것이 목표입니다. 그래서 "더 하세요"처럼 부담을 주는 문구는 쓰지 않습니다.
  - 제안 문구: "오늘 놀이 잘 마쳤어요. 아이가 더 놀고 싶어 하면 하나 더 해 봐요."

## 4. 커뮤니티 글 상세 화면과 댓글 (P1)

**지금**
- 목록에 "댓글 N"이라는 개수만 보이고, 글을 눌러도 내용과 댓글을 볼 수 없습니다.
- 글 상세 화면이 없습니다.

**제안**
- 글 상세 화면 `/community/[id]`를 만듭니다.
  - 위쪽: 제목, 본문, 닉네임, 시간, (있으면) 연결된 놀이 카드
  - 아래쪽: 댓글 목록과 댓글 입력창
- 댓글 규칙
  - 로그인한 부모 누구나 읽을 수 있습니다.
  - 자기 댓글만 지울 수 있습니다. `supabase/schema.sql`의 `comments` 정책에 이미 있습니다.
- 안전 장치는 #13에서 만든 것을 그대로 씁니다.
  - 효과를 단정하는 표현에는 '검증되지 않은 정보' 표시를 붙입니다.
  - 실명·사진 주의 안내도 댓글 입력창 위에 보여줍니다.
- 신고 버튼은 `post_reports` 테이블이 이미 있습니다. 시간이 되면 함께 만듭니다.

## 5. '다른 놀이'를 누르면 영역 고르기 (P1)

**지금**
- [다른 놀이]를 누르면 다음 놀이가 자동으로 바뀝니다.
- 부모가 "오늘은 몸 놀이를 하고 싶다"처럼 원하는 영역을 고를 수 없습니다.

**제안**
- [다른 놀이]를 누르면 아래에서 영역 선택 창(바텀시트)이 올라옵니다.

```
어떤 놀이를 해 볼까요?
[ 추천대로 ]  ← 기본 (지금처럼 자동)
[ 소리 놀이 · 언어 ] [ 생각 놀이 · 인지 ] [ 주고받기 놀이 · 사회성 ]
[ 몸 놀이 · 대근육 ] [ 손 놀이 · 소근육 ]
```

- 영역을 고르면 그 영역에서 월령과 단계에 맞는 놀이를 보여줍니다.
  - 단계는 설문 결과(`startStep`)와 지난 기록을 반영합니다.
- 지원이 더 필요해 보이는 영역(설문의 `focus`)에는 **"추천"** 표시를 붙입니다. 선택은 부모에게 맡깁니다.
- 영역 이름은 홈 인사말에 쓰는 이름(`AREA_PLAY_NAME`: 소리·생각·주고받기·몸·손 놀이)을 그대로 씁니다.

## 6. 아이 정보에 관심 놀이와 더 함께하고 싶은 영역 추가 (P2 / 시연용이면 P1)

**배경**
- 부모는 설문 전부터 "말이 늦어요"처럼 신경 쓰이는 영역을 알고 있는 경우가 많습니다.
- 아이가 좋아하는 놀이(예: 몸으로 노는 것)로 시작하면 놀이를 꾸준히 하기 쉽습니다.

**제안: 아이 정보 입력에 선택 질문 2개 추가** (건너뛸 수 있음)

| 질문 | 선택지 | 쓰임 |
|---|---|---|
| 우리 아이가 좋아하는 놀이는? (여러 개 선택) | 소리 놀이 · 생각 놀이 · 주고받기 놀이 · 몸 놀이 · 손 놀이 · 잘 모르겠어요 | 같은 조건의 놀이가 여러 개일 때 좋아하는 종류를 먼저 보여줍니다 |
| 더 함께 놀아 주고 싶은 영역은? (여러 개 선택) | 언어 · 인지 · 사회성 · 대근육 · 소근육 · 잘 모르겠어요 | 오늘의 놀이 영역을 정할 때 우선합니다 |

- 문구는 "발달이 느린 영역"이 아니라 **"더 함께 놀아 주고 싶은 영역"**으로 씁니다.
  - 진단처럼 들리지 않게 하고, 부모가 부담 없이 고르게 하기 위해서입니다.
  - 질문 아래에 "진단이 아니에요. 집에서 본 모습대로 골라 주세요"를 넣습니다.

**오늘의 놀이 추천 순서 (제안)**
1. **영역 정하기**
   - 부모가 고른 '더 함께하고 싶은 영역'과 설문의 `focus`를 합칩니다. 두 곳에 모두 있는 영역이 1순위입니다.
   - 설문을 하지 않았으면 부모가 고른 영역만으로 정합니다.
2. **단계 정하기**: 설문 `startStep`과 기록 반응으로 정합니다. 지금 규칙 그대로입니다.
3. **놀이 고르기**: 같은 영역과 단계에 놀이가 여러 개면 '좋아하는 놀이' 종류를 먼저 고릅니다.
4. **균형 맞추기**: 최근 3번이 모두 같은 영역이면 덜 해본 영역으로 바꿉니다. 지금 규칙 그대로입니다.

- 설문을 다시 하면 결과 화면에서 "선택한 영역도 함께 볼까요?"처럼 연결할 수 있습니다.

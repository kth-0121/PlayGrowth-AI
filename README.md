# PlayGrowth-AI

발달지연이 걱정되는 아이의 부모가 **센터 치료를 기다리는 동안** 집에서 할 수 있는 놀이를 AI가 추천하고, 잘하고 있는지 기록과 진척으로 확인시켜 주는 모바일 웹 서비스입니다.

> ⚠️ 이 서비스는 진단이나 치료가 아닙니다. 앱 안의 문구에서 "처방", "치료", "진단"이라는 표현은 쓰지 않습니다.

## 왜 필요한가
- 발달재활 센터 대기 기간이 3개월 이상 → 그 사이 조기 개입 시기를 놓침
- 월 치료비가 최대 180만원이고 대부분 건강보험이 적용되지 않음 (전국장애인부모신문, 2026.10.26)
- 부모가 인터넷 검색으로 집에서 시도하지만 **이게 맞는지 확인할 방법이 없음**

## MVP 기능
1. **온보딩**: 아이 월령 입력, 보호자 동의
2. **수준 체크**: 6개 영역(대근육·소근육·인지·언어·사회성·자조) 문항 → 지원이 필요한 영역 1~2개 선정, 위험 신호(red flag)가 있으면 전문가 상담 안내
3. **오늘의 놀이**: 10분짜리 놀이 1~2개. 감수받은 라이브러리 안에서만 AI가 골라 추천
4. **놀이 기록**: 했는지, 아이 반응(3단계), 메모
5. **진척 리포트**: 주간 요약. 센터에 처음 방문할 때 보여줄 수 있는 화면

나중에 추가: 영상 분석, 센터용 대시보드, 결제

## 기술
Next.js (App Router, TypeScript, Tailwind) · Supabase (인증/DB) · Claude API

```bash
npm install
cp .env.example .env.local   # 키 입력
npm run dev                  # http://localhost:3000
```

## 구조
```
src/app/            화면 (프론트엔드)
src/app/api/        추천 API (AI)
src/types.ts        팀 공통 타입 ← 계약
data/plays.json     놀이 라이브러리 ← 계약
supabase/schema.sql DB 스키마 ← 계약
```
**계약 파일 3개**(`src/types.ts`, `data/plays.json` 형식, `supabase/schema.sql`)를 바꾸려면 PR을 올리고 팀원 전원의 확인을 받아야 합니다.

## 협업 규칙
- **`main`에 직접 push 금지**: 브랜치를 만들어 PR을 올리고 1명 이상 승인을 받은 뒤 merge
- **브랜치 이름**: `feat/이슈번호-내용`, `fix/이슈번호-내용` (예: `feat/3-onboarding`)
- **커밋 메시지**: `feat: 온보딩 화면`, `fix: 기록 저장 오류`, `docs: README 수정`
- **PR 본문**에 `Closes #이슈번호`를 적으면 merge할 때 이슈가 자동으로 닫힘
- **작업은 이슈 단위로 진행**: 칸반 보드의 할 일 → 진행 중 → 완료 순서로 옮김
- **API 키**는 `.env.local`에만 저장 (커밋 금지)

## 일정
- **1주차**: 계약 파일 확정, 놀이 초안 10개, 화면·DB·추천 API의 기본 틀
- **2주차**: 5개 화면 연결, 놀이 50개, 추천 점검 스크립트
- **3주차 이후**: 부모 5~10명 대상 2주 파일럿
